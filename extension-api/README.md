# extension-api/: interim copy of the engine extension API

The engine customises Command Center only through the extension points of 08 §4.3:
`cc.config.ts`, `theme/tokens.json`, widgets in `ui/`, framework and pack files, and
`connectors.lock` (C-08-08). The foundation owns their contract and validators, and the engine
holds no foundation code. That contract lives in packages the foundation has not published yet,
so this directory carries a self-contained copy of extension API 1 until it does.

| File | Stands in for | What it is |
|---|---|---|
| `v1/engine.ts` | `@cc/schemas/engine/v1` | zod schemas for `cc.config`, theme tokens and `connectors.lock`; `EXTENSION_API_CURRENT`, `EXTENSION_API_SUPPORTED` (ADR 0003 decisions 1 to 4) |
| `v1/tokens.ts` | `@cc/schemas/engine/v1-tokens` | token paths and the closed value grammar; safe to import from `ui/` |
| `v1/slots.ts` | the slot list of `@cc/ui-sdk/v1` | the slots widgets may register for (decision 5) |
| `v1/ui-sdk.d.ts` | `@cc/ui-sdk/v1` | type declarations for `defineWidget` and `token`; no runtime |
| `v1/*.schema.json` | generated by `@cc/schemas` | JSON Schemas for editors and non-TypeScript tools; generated by `pnpm cc:schemas`, never edited by hand (C-08-03) |

`tsconfig.json` maps the package names above to these files, so engine code already imports
the final names (`import type { EngineConfig } from '@cc/schemas/engine/v1'`). The scripts in
`tools/` (`cc:validate`, `cc:path-guard`, `cc:harness-check`, `cc:lock-verify`) are the
engine scripts 08 §6 says come from `@cc/build`.

**Removal (P1-16).** When the `@cc/*` packages are published, the engine template pins them
exactly; this directory, the `paths` in `tsconfig.json`, and the interim scripts in `tools/`
are deleted, and `package.json` runs the same commands from `@cc/build`. A change to this
contract before then follows the foundation's `cc-change-extension-api` skill: additive
changes keep API 1; a breaking change bumps the API and ships a codemod (ADR 0003 decision 6).

Extension API 1 starts from the shapes ADR 0003's prototype settled on (its "API 2"):
`modules` as `{ id: boolean }`, `calendars` (02 §9.6), nested `color.accent` tokens, and
`defineWidget` with a required `title`. The prototype's API 1 shapes never shipped.
